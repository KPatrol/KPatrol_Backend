## [1.0.0] — 2026-05-25

Graduation-thesis release: source-of-truth API for the K-Patrol V10 prototype demo.

### Added

#### Alarm rule engine
- `AlarmRule` Prisma model with 4 notification-fan-out columns:
  - `notifyOwner` (boolean, default `true`) — route to robot owner
  - `notifyAdmins` (boolean, default `false`) — broadcast to admin role
  - `notifyEmail` (string, optional) — CSV of extra email recipients
  - `notifyZaloIds` (Json array, optional) — explicit Zalo OA user IDs
- `AlarmRuleController` + `AlarmRuleService`: full CRUD per robot, validates email
  format and caps `notifyZaloIds` length to 10. Publishes `alarm_rules_updated`
  on change so the Pi alarm engine hot-reloads.

#### Notification module
- `NotificationService.notifyForAlarmRule(rule, trigger)`: resolves
  owner/admins/email/zaloIds from `AlarmRule.notify*`, deduplicates recipients,
  then fans out via `EmailChannel` + `ZaloChannel`.
- `ownerEmailOverride` from `NOTIFY_OWNER_EMAIL_OVERRIDE` env so deployments
  where the owner's account email has no MX records can still receive alerts.
- `POST /api/notifications/test-send` for manual SMTP verification.

#### Email channel (HTML)
- Bulletproof table HTML with K-Patrol logo CID inline (`assets/logo.png`).
- Dark cyan theme + severity color strip + "Mở Cockpit" CTA.
- Falls back to plain text when `SMTP_HOST` is unset (dev mode).

#### MQTT ingest
- `MqttIngestModule`: subscribes to EMQX, persists telemetry/heartbeat/safety/
  detection events, fans out over Socket.io with throttled DB writes.
- `handleAlarmTriggeredMessage`: persists the trigger row + invokes
  `notifyForAlarmRule` immediately so alerts hit operators within seconds.

#### Auth hardening
- Rate-limits via `@nestjs/throttler` on the public attack surface:
  - `/register` 10/min (bcrypt is expensive on purpose)
  - `/login` 20/min
  - `/refresh` 30/min
- DTO `MaxLength` caps on email/password/name to reject multi-MB payloads.

#### Robot + Socket
- Robot lifecycle hooks for telemetry-driven battery alerts.
- Socket.io user-scoped dashboard room `dashboard:<userId>` so per-tenant
  telemetry/event broadcasts don't leak across users.

### Changed

- `Dockerfile`: multi-stage build copies `assets/` into the runtime image so
  the email logo CID is available without a separate volume mount.
- Prisma schema reformatted (consistent indentation, removed legacy comments).

### Security

- All SMTP/MQTT credentials and JWT secrets live in `.env` (gitignored). Only
  `.env.example` template is tracked.
- Per-rule notification routing means a leaked operator account cannot route
  alerts to unauthorised recipients without an admin's rule update.
